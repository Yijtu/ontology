# Ontology 知识工作台

把某个业务领域，从**料源**整理成**可审核、可追溯的行业资产**，再用固定版本完成**带依据的业务问答**。

资料、业务定义、规则与项目数据在同一条工作流程里流动：你可以确认来源类别、核对候选、裁决身份、发布正式事实，也可以沿答案回到原文和历史版本。核心价值是可审核、可追溯、可固定：**没有经过人工审核和发布的内容，不会进入正式查询范围。**

## 第一屏：进入工作台

打开首页就是「工作概览」，第一屏给出入口，不要求先理解 agent、mapping 或本体工程，也不要求先选内置演示行业。

- **两个工作台**（顶部切换）：
  - **行业工作台**：整理领域的对象、属性、关系、规则与动作，审核并发布可复用的行业包。
  - **项目工作台**：挂载已发布行业包，确认实际业务数据，完成带依据的任务与问答。
- **知识从哪里来（三料源）**：
  - **AI 搜寻公共资料**——填写业务目标与研究范围，确认外发范围与额度后开始调研。调研是一个受控 agent：在授权范围内多轮检索、归档页面、定向精读、组合多来源，最后通过受控命令提交候选；结果只产候选，来源类别由你确认。搜索次数、归档来源数、候选数、读取字节与死线都在同一份额度账本上计量，超限即拒，不能靠重试绕过。
  - **上传或粘贴资料**——文本、CSV、Excel 等；上传只登记原料，不自动证明权威性，按「行业依据 / 项目记录」两条用途分流，两种用途各自审核与授权。
  - **接入结构化数据**——首期是文件映射快照：选文件 / sheet / 列，预览原值与规范值，确认映射；数据库连接属于规划能力。
- **现在需要你处理**：待办由服务端从已读取的真实状态推导（来源待确认、工作区待审核、项目待确认等），点击直接进入对应操作，不显示无法解释的百分比。
- **AI 设置**：位于「设置」下，分为「模型连接」「能力与工具」「默认与分配」「生效详情」，另有兼容旧的整实例配置页签。「能力与工具」维护搜索等外部工具的连接目录与分配，并可探测连接是否可用——探测通过只说明可达，不代表结果质量。

### 上手路径

1. 在首页输入业务目标，点「创建行业工作区」（第一步只需要名称 + 业务目标）；如果已经有可用的行业包，点「使用已有行业包创建项目」。
2. 行业工作台按「来源准备 → 资产审核 → 验证发布」推进，项目工作台按「项目准备 → 带依据问答」推进。「工作进度」与「现在需要你处理」显示当前阶段与下一步。
3. 需要模型能力时再配置模型；默认关闭外部模型，未配置模型不影响已有资料、历史与确定性任务。

## 本机跑起来

需要 Node.js 22+、pnpm 和已启动的 Docker Desktop。下面从仓库根目录开始，在 PowerShell 中运行；三个端口需空闲。

```powershell
cd platform
pnpm install --frozen-lockfile

$coreProject = 'ontology-core-demo'
$env:CORE_API_PORT = '3001'
$env:CORE_WEB_PORT = '5174'
$env:CORE_PG_PORT = '54330'
$env:CORE_POSTGRES_PASSWORD = Read-Host '设置本机演示数据库密码'
$env:CORE_ENABLE_OPERATOR_ROUTES = 'true'
$env:CORE_ENABLE_MODELS = 'false'
$env:CORE_ENABLE_JEV = 'false'
$env:CORE_OBJECT_DIRECTORY = Join-Path (Get-Location) '.core-data/objects'

docker compose --project-name $coreProject --file deploy/core/compose.yaml up --detach
$corePassword = [uri]::EscapeDataString($env:CORE_POSTGRES_PASSWORD)
$env:CORE_CONTROL_DATABASE_URL = "postgresql://postgres:$corePassword@127.0.0.1:$($env:CORE_PG_PORT)/ontology_core"
pnpm exec tsx scripts/prepare-core-db.ts
pnpm exec node scripts/dev-core.mjs
```

就绪后打开 **[http://127.0.0.1:5174](http://127.0.0.1:5174)**。准备命令应用当前迁移并生成本地配置；原件保存在 `.core-data/objects`。停止、重启、独立实例和更多配置见[本机启动指南](platform/docs/core-local-startup-2026-09-28.md)。已有同名演示环境时，先按指南选择独立项目与端口。

### 作为服务端共享（远程客户端）

本机默认只监听回环地址，且默认只接受回环开发身份。要让另一台机器上的客户端访问，需要显式放开监听、配置访问令牌，并先构建前端产物——API 会同时托管这份 UI，客户端因此与服务端同源，不需要开放 CORS：

```powershell
pnpm run build:web

$env:CORE_API_HOST = '0.0.0.0'                                   # 默认 127.0.0.1
$env:CORE_API_TOKEN = '<长随机令牌>'                              # 设置后只接受 Bearer 令牌
$env:CORE_API_TOKEN_SUBJECT = 'deployment-token'
$env:CORE_WEB_DIST = (Join-Path (Get-Location) 'apps/web/dist')  # 可选，默认同路径

pnpm exec node scripts/dev-core.mjs
```

客户端请求带 `Authorization: Bearer <令牌>`；`/healthz` 保持免认证，便于客户端先探活。**令牌作用于整个租户/空间**，是部署级共享凭据，只适合受信网络；对外暴露前需要接入 OIDC。TLS 由反向代理终止，客户端不会忽略证书错误。设计见[Electron 客户端 + 远程服务端](tasks/design-electron-client-2026-10-21.md)。

桌面客户端在 [`client/desktop`](client/desktop/README.md)：它加载的就是上面这份服务端托管的 UI，只负责窗口、地址配置、令牌（系统凭据存储）与断线提示。

## 现在能做什么

- **读资料，建业务知识。** 把一份资料按用途登记为行业依据或项目记录，为定义与规则候选绑定真实来源，经人工审核和独立题集验核后发布固定版本。
- **让 AI 做受控调研。** 调研有工具、有额度、有死线：检索、归档、精读都限定在授权范围内，多来源证据可组合，但产出只到候选。取消、超时、预算耗尽都会留下明确的停止原因，不会留下一条无人拥有的「进行中」记录。
- **审核并纳入来源。** 交接视图逐个列出候选引用的来源和阻塞原因：**来源未确认**、**未准入**、**需要重新接地**。审核只记录人工判断，提级是独立的平台管理员动作；来源准入后才进入建模文档集，而引用它的候选必须**重新接地**生成新版本（旧版本保留），才能进入资产审核。越权、版本冲突、无可归档快照都会拒绝并给出原因；撤回与重新分类保留历史。
- **把项目数据变成正式事实。** 文件映射接入，确认列对应、核对单位与身份；只有完成相应审核与发布的数据才进入正式查询范围。
- **执行任务，查看依据。** 运行已发布规则、登记过的计算及资料问答，查看结果、来源和历史。业务查询支持 DuckDB 与独立 PostgreSQL 后端。
- **让版本继续往前走。** 对新版本重新映射与抽取，可取消、审核、激活或撤回，并保留旧答案与其固定依据。
- **管理外部模型与工具。** 在 AI 设置里维护模型连接目录、工具连接目录，按能力/对象分配并查看生效来源；连接测试只验证可达，不代表业务质量。

## 边界与诚实声明

- **默认关闭外部模型。** 结构化导入、人工审核、确定性任务和历史回读无需调用外部模型；自动生成和模型问答需另行配置连接。连接测试通过 ≠ 业务质量。
- **内置场景是合成演示。** 仓库内的行业与资料为合成样例，用于演示与验证；合成与真实项目事实严格隔离。
- **真实模型质量与外部服务需单独验收。** 搜索侧已接入原生 Tavily 适配器与兼容网关，但真实 Tavily 账号、配额与结果质量、归档域名授权，以及客户生产系统（数据库、向量库、DataOS 等）接入都未在本阶段验收；本阶段的受控响应只替代了模型/搜索的 HTTP 边界。
- **本阶段承诺的资料格式**：UTF-8 文本、JSON、CSV、XLSX（表格可选 sheet、确认列对应、预览规范值与原始单元格）；项目文档用授权文本片段做检索与有引用问答。**PDF、扫描件、DWG 与数据库连接不在本阶段承诺范围**，需单独规划；PDF 现有行业路径保留，OCR 与项目入口未纳入。
- **本仓库 main 只承载通用 Core 能力与公共前端**，不含具体行业/客户业务内容（如造价）；场景专属资产、扩展与专业 UI 维护在各自的场景分支。
