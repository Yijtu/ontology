# V03-020：实现项目、资料映射与就绪状态公共前端

阶段 A · frontend · P1 · 状态 planned · GitHub [#193](https://github.com/Yijtu/ontology/issues/193)

执行工作线：feat/core-planning-provenance；目标：main。本批尚未开始实现；V03 是规划 ID，GitHub 编号见上述链接与 manifest。

## 目标与范围

- 业务助手可以创建项目、挂载包、上传/选 sheet/调列映射、查看记录与 semantic/query/index 独立就绪。
- 每阶段行数、失败位置、字段确认和未就绪修复入口可操作，不要求普通用户填数据库/runtime JSON。
- 浏览器验证新导入记录与semantic/query/index就绪投影、分页/重复导入/修订/范围拒绝和错误后的页面保留；正常NL/工具查询结果由025/040/045接通验收。
- 提供按行业Schema人工新增业务记录与补参表单，回读manual-entry来源/审批/修订；输入非原文件时仍有可核验真实来源。

## 需求与规格

- [asset-data-ui.md](../../../../../tasks/spec-v0.3a/asset-data-ui.md)

故事范围：A.US-001、A.US-002、A.US-006、A.US-012。逐项覆盖见[覆盖表](../../coverage.md)。

- A.US-001.AC-01 → A-T001-01：行业包与项目首页支持创建、继续、切换及刷新回读；没有造价模块时不显示默认报价操作。
- A.US-002.AC-01 → A-T002-01：支持表中四类格式；CSV／XLSX 可选择 sheet、确认列对应、预览规范值与原始单元格。

- A.US-002.AC-04 → A-T002-04：在浏览器核验分页、失败行、重复文件、修订与来源对照。
- A.US-006.AC-04 → A-T006-04：在浏览器及 API 核验新导入数据、映射变更、失败恢复和跨项目读取拒绝。
- A.FR-1 → A-F01：系统必须提供独立可操作的两个公共助手入口。
- P.US-001.AC-02 → P-T001-02：A 的业务首页显示项目、新建项目和当前已挂载任务；本体首页显示行业包、创建行业包、继续建模。B 挂载“AI 造价师／请求报价”入口。
- P.US-012.AC-01 → P-T012-01：可建立项目、输入业务目标、选择已发布行业包；页面显示项目、行业、客户范围和所用版本。
- P.US-012.AC-03 → P-T012-03：已有项目不自动切到行业包新版本，切换形成新修订并展示影响。
- P.US-012.AC-04 → P-T012-04：在浏览器核验建项目、挂载、未就绪和版本切换。
- P.US-013.AC-05 → P-T013-05：在浏览器核验上传、分页、重复导入、失败行和项目隔离。
- P.FR-15 → P-F15：系统必须分别显示语义发布状态与部署执行能力。
