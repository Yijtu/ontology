# 公共前端升级：视觉、交互与验收

2026-10-08。用户追加要求：现有界面粗糙简陋，前端必须纳入本批修改。基线 `43525be`（PR #250 已合入）；本文件是实施准则，配套[可交互界面方案](frontend-design.html)。方案使用合成示例，只演示页面与交互，不代表生产 API 或模型能力已经实现。

## 目标

做一套适合连续工作、能读懂状态、能沿来源完成审核的产品界面。功能完整与视觉质量均为验收门槛。首页挂一排入口、散落表单套卡片或只改配色，均不能满足本次要求。

界面采用白色内容面、浅灰工作背景、深色文字与低饱和青绿色主色。字体使用系统中文字体，无外部字体依赖；主标题 24–28px，正文/表格 14px，辅助信息不低于 12px。采用 4/8px 间距尺度、6–10px 控件圆角、轻分割线；状态通过文字与图形共同表达，避免大面积渐变、巨型卡片与装饰性统计。

## 信息架构

全局只保留少量工作路径：

| 主入口 | 工作内容 |
|---|---|
| 工作概览 | 当前项目/本体进度、真正待处理事项、最近运行；没有数据时引导新建或导入。 |
| 本体建模 | 资料 → 候选 → 人工审核 → 能力问题验核 → 行业包发布与版本比较。 |
| 项目数据 | 原文/表格导入 → 列映射 → 字段与身份确认 → 事实/查询就绪 → 换版重提取。 |
| 业务实践 | 已挂载任务、自然语言/参数表单、澄清、运行进度、已核验结果与来源。 |
| 行业资产与历史 | 可复用版本、历史运行与证据；以主入口内的上下文链接为主要到达方式。 |

模型/工具配置与原始 JSON 进入高级区。现有部署贡献的行业专属入口保留，通过声明注册；公共导航不按行业名称硬编码。

侧栏负责导航。顶栏只放当前项目/工作区、版本状态与全局操作；页面工具栏放搜索、筛选和本页操作。一次展示一个最主要的下一步，避免同屏放多组同等强调的按钮。普通使用路径不要求填写 UUID、digest、schema 引用或 recorded 序号。

## 本体工作台

桌面采用“候选列表—结构化详情—原文依据”三栏。列表可搜索/按对象属性关系规则动作与状态过滤；详情展示业务含义、定义、关系端点、单位和问题；依据显示原文高亮、资料版本和定位。小屏切成列表/详情/依据视图，主操作仍可达。

- 上传先展示文件、解析覆盖与失败原因，生成过程展示可解释的阶段与取消。
- 审核、编辑、拒绝各自独立；修改前预览影响，修改后明确需重新审核。批量审核仅对满足条件的真实候选开放。
- 对象/属性/关系用字段表单；规则使用有限条件、分组和例外编辑器，提供自然语言摘要；动作从已注册操作选择。高级 JSON 可折叠查看/编辑，但仍需运行时校验。
- 发布前按“审核状态、能力问题、兼容性、部署能力”展示检查结果，阻断项能回到具体候选或问题。破坏性策略说明受影响对象、需迁移项目与历史保留方式。
- 版本 diff 用新增/更改/删除分组和具体字段前后值；不可仅显示摘要字符串或一段 JSON。

## 项目与业务工作台

项目导入采用逐步流程：文件预览、列映射对照、单位/必需字段校验、未确认记录、身份裁决与发布进度。表格有稳定表头、数字右对齐、行状态、分页与来源入口，滚动和筛选不改变固定版本。

业务页面以“结论—正式结果表—依据”为主线。发起任务时先解释项目尚缺哪项就绪条件；参数由真实 schema 生成表单，自然语言歧义通过澄清处理。查询/规则/关系/compute 的执行细节放进展开区，内容与按钮不暴露装配代码。

来源使用可收回的侧面板，从结论逐级显示规则版本、事实/上游结论和原文/单元格。用户保留当前列表位置和问题上下文，关闭后焦点回到触发按钮。大表默认使用正式工件分页，不把截断摘要误当完整结果。

## 状态体系

| 状态 | 用户看见的内容与可操作路径 |
|---|---|
| 初次/空数据 | 简短说明、一个主要下一步、必要的样例说明；没有虚构统计。 |
| 加载/处理中 | 稳定占位、任务阶段、取消/稍后查看；布局不大幅跳动。 |
| 待审核/缺字段/身份冲突 | 明确数量与位置，进入具体待办，保留未完成输入。 |
| 未知/冲突/部分覆盖 | 明确哪些结论无法确定和缺什么依据；不能画成成功勾。 |
| 模型关闭/能力缺失 | 展示仍可使用的显式任务，说明生成/NL 尚未就绪。 |
| 无权限/只读 | 保留可读资料，写操作显示原因；不靠隐藏按钮假装状态正常。 |
| 网络/解析/任务失败 | 可理解的失败位置、能否重试、已有结果与输入保留；技术追踪 ID 放展开详情。 |
| 取消/撤回/旧版本 | 说明本次运行与当前有效性，历史可读但不得显示仍在生效。 |

## 完成标准

- 在 1440/1024/768/390px 分别核对主流程。页面级无横向溢出；宽表格可在自身容器内滚动，关键状态与操作可读。
- 满足 WCAG 2.2 AA 的适用项：文本/控件对比、可见焦点、语义 label、键盘操作、抽屉焦点返回、非颜色状态、触控目标与 reduced-motion。以真实浏览器检查为准，不把属性存在当成验收完成。
- 正常应用 URL 经三条完整用户路径成功，含撤回/失败/取消/权限/模型关闭/未知冲突；不能以 harness 或全链路 mock 替代。
- 检查固定已核验版本、跨项目切换和旧结果有效性；界面不得把流式草稿或取消迟到结果显示为已核验结果。
- build/typecheck、受影响 UI 检查与真实 chromium E2E 全过；视觉与交互有截图证据，明显粗糙仍需迭代。

[W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/) 是可访问性依据。本方案不引入新的前端框架或组件平台；优先利用当前 React/TypeScript 及声明式场景挂载接口。
