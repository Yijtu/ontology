## 工程边界

行业定义和客户物理映射保持分开；通用应用通过端口读取数据，不直接依赖行业实现。合成资料保留来源标签。数据查询与控制、审核、证据数据库分开。密钥不进入行业包、页面或提交。

默认启动器是带合成场景配置的 Core 宿主：它要求至少挂载一个场景，并校验示例分类。可通过 `CORE_DEPLOYMENT_CONFIG` 换示例索引；这不等同于已经完成生产行业包安装、零场景启动或任意客户数据源接入。

开发工作区的未提交文件保留原位，用户正在使用的其他工作区与本地服务不做切换或清理。合并验证在独立的 `ontology-core-main` 工作区运行。

验证命令与实际结果在合并完成前补入下节；模块测试、受控模型调用和真实客户验收分别报告。

## 合并验证

首次干净检出暴露了示例文件换行转换问题：Windows `core.autocrlf=true` 把政策文本改成 CRLF，使已登记内容摘要失配。新增 `.gitattributes` 固定示例资产为 LF；摘要与断言保持不变，并通过 Git checkout filter 复核实际字节和摘要。资产测试的 Windows 专属路径拼接也改为平台路径 API。

上述修复后，资产/loader/facts/API/UI/正常 Core HTTP 六套测试 38/38 通过；Node 启动器六项、完整 ESLint、三项目 TypeScript 和 Web build 已通过。第一轮完整 Vitest 的其他失败涉及旧规则/身份夹具和未实际执行语义核验的质量探针；完成有针对性的修复后重新执行合并回归，最终结果随后记录。
