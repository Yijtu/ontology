# GAP-022 前端验收记录

本文记录 Node 22 普通 App 的端到端接线范围和实际证据。它不是全量通过或合并声明；Root 正在修复并重跑 Generic 全套测试，README 与主分支状态由后续收尾决定。

## 普通 App 流程

### 1. 创建并发布本体规则包

[generic-assistants.v03.e2e.ts](../tests/e2e/generic-assistants.v03.e2e.ts) 中的 Flow 1 从实际 App URL 开始：用户创建工作区、上传政策原始字节、读取原文、选择来源片段并确认候选来源。生成模型由本地受控 HTTP provider 响应；工作区、来源、候选、审批、验核和包发布都由实际 Core 服务及 PostgreSQL 完成。

工作流分别核对定义来源确认与人工内容审批、规则来源确认与人工审批/启用、独立编写的合成测试输入和期望、题集实际保存与服务端生成引用的回读、题集人工审批、服务端可发布验核报告和不可变包发布。刷新后恢复 `?view=ontology&workspace=…` 深链及实际工作区选择。生成候选和题集引用均采用服务端返回的版本与摘要。

### 2. 从 CSV 到正式项目事实和数据集

[project-pipeline.core.v03.e2e.ts](../tests/e2e/project-pipeline.core.v03.e2e.ts) 覆盖真实 App 项目工作台：选择注册场景、导入浏览器提供的 CSV、预览并确认映射、绑定记录、逐字段人工确认、人工确认对象身份、批准并发布记录。映射记录确认与正式语义事实发布是两道独立步骤；随后通过可见项目操作物化数据集，并从字段来源界面重读原始 CSV 单元格。

项目显示使用实际目录中的字段名称；名称缺失时以实际映射表头或字段标识回退。记录表在窄容器内改为逐字段卡片；桌面宽屏保留表格布局。

### 3. 使用刚发布的包执行规则任务

Flow 3（同见 [generic-assistants.v03.e2e.ts](../tests/e2e/generic-assistants.v03.e2e.ts)）从 Flow 1 实际发布的精确包引用开始。用户在项目版本选择器中选择该版本；App 调用真实 `published-pack-profiles` 配置端点并用返回的业务项目 profile 创建项目。之后通过实际 CSV、映射、记录字段和身份确认、记录发布、Candidate Review 独立语义发布及数据集物化完成正式事实链路。

用户在“业务任务”界面选择真实注册的 `core.task.rule_judgement`，从服务端任务 Schema 提供的选项中选择实际规则与已确认实体，预览并确认参数后运行。验证读取服务端发布的 V3 答案，并检查规则判断轴为 `applicability`、值为 `true`；该判断不被表述为业务命题“必须检修”为真。运行期间智能判断模型请求数不增加。

答案引用的来源按钮按 V3 答案中该规则断言的实际 `premiseRefs` 定位；来源面板重读本次浏览器上传 CSV 的原始 `B2=true` 单元格，并核对回读原始文件的 ID 和摘要与导入响应一致。完整证据页的证据 ID 与该 premise ref 相同。

## 视口和可访问性证据

普通 App 页面在 1440、1024、768、390 和 320 像素宽度运行；项目流程检查页面宽度无横向溢出，截图包括 `gap22-project-materialized-{width}.png`。Flow 1 保留工作区、原文、候选、验核和发布截图；Flow 3 保留规则结果、来源单元格及完整证据页截图。文件位于本地 E2E artifact 目录 `platform/tests/e2e/artifacts/`。

项目浏览器验收使用 [real-app-accessibility.ts](../tests/e2e/real-app-accessibility.ts) 采样实际标签关联、可见控件、计算文本对比度、`prefers-reduced-motion`、键盘焦点指示、对话框 Tab 循环、Escape 关闭和焦点返回。默认表单边框经实测修正后，Root 在 1024/768 宽度复看记录字段可读性；320 宽度记录字段为堆叠布局。

这些是列出的控件与状态的实际采样，不等于全站 WCAG 2.2 AA 认证。未覆盖的非文本边框和焦点表面不会据此宣称已测量。截图与采样分别记录在 E2E artifacts 和运行日志中。

## 测试边界与当前状态

- 模型替代只限生成模型 HTTP 边界；这是受控 provider 结果，不代表真实模型质量。规则任务运行使用已注册确定性任务，未调用模型判断。
- Flow 1 样例为 `synthetic`，保留业务审批 `none` 与未写入客户事实的边界。样例验核不等于客户验收、生产质量或业务审批。
- Flow 3 的 `rule_judgement` 只证明规则适用性，不推导业务命题。真实规则版本、项目输入、答案、premise refs 和原始单元格分别按服务端返回值核对。
- Root 已独立运行最终 Flow 2 浏览器与可访问性回归：1/1 通过，29.80 秒；含五个宽度、严格 worker 诊断和资源清理。Flow 1+Flow 3 曾以专门筛选用例 2/2 通过，53.21 秒；这是此前 scoped run 记录，不代替更新后的完整套件复验。
- Generic 完整 13 项套件最近运行仍发现需要修复的旧测试依赖和错误归属问题。Root 正接续修复并重跑；因此本文不宣称完整 Generic 全套、CI、最终主分支或节点合并已通过。
