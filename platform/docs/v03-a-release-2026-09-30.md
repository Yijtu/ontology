## 1. 范围与交付

A 阶段交付“通用双助手 Core”的完整正常路径与可替换性验收：

- 结构化资料导入 → 候选 → 定义/规则/动作审核 → 动态发布包 → 挂载。
- 客户项目：绑定、字段映射、三种就绪、查询投影与文档索引。
- 任务化运行：已发布属性事实、结构化查询、文档问答、规则判定、注册计算。
- typed `answer@3`：逐字段硬核验、全表/1001 行分页核验、发布有效性（validity/fence）、
  修订历史与已核验 JSON 导出。
- 两行业 / 两后端 / 两运行时 / 真实 stdio MCP 的可替换性一致性套件。
- 真实 chromium 浏览器 E2E：导入→身份→发布→事实链，以及计算/文档问答/规则判定任务类型。
- 公共 UI 权限、未就绪、错误恢复状态。

不含（按 SPEC §9 与任务卡边界）：真实客户资料与报价、真实外部模型质量、生产认证、
外部实机设备控制。

### 如何应用

迁移由**显式步骤**应用，服务启动不会自动升级数据库：

```text
CONTROL_DATABASE_URL=postgres://<owner>@<host>:5432/<db> \
  pnpm --filter @ontology/adapter-control-postgres migrate:control
```

`runControlMigrations` 持有 PostgreSQL advisory lock，记录已应用版本 + SHA-256 校验和
（`agent_platform.control_schema_migrations`），跳过已应用版本，已应用文件内容变化会失败。
详见 [migrations/control/README.md](../migrations/control/README.md)。

## 7. 独立审查记录

`/review-it` 技能在本 agent 中无对应 `/review` 命令可用，故按任务卡与 AGENTS.md
Code Review Rules **手工严格审查** 集成增量（`main..feat/v03-assistants-core`，81 提交 /
529 文件），重点覆盖：跨层依赖、租户隔离、预算/取消、证据丢失、时态与撤回、
未经核验发布、模拟/实机混淆。

结论：**未发现阻断性缺陷。** 逐维度核对与发现如下。

- **跨层依赖**：`pnpm run boundaries`（8 项）通过；新增应用层只经端口/装配注入适配器，
  未发现 contracts 引入框架/行业实现，或跨包深层私有导入。
- **租户隔离**：全部新增租户表（058–077，18 个迁移）均带 `tenant_id`/`space_id` 主外键 +
  RLS + `scope_isolation`（逐文件核对 `ENABLE ROW LEVEL SECURITY` 与策略）。运行路径的
  可信 scope 均取自 host-minted `ToolContext`（如 `publication-validity.ts`、计算 reader、
  项目文档服务），请求 body 不覆盖 principal。
- **预算/取消**：load 故障注入覆盖并发预算争用与迟到取消，均 PASS；
  取消后的迟到结果不恢复、不发布。
- **证据丢失**：`PublicationValidityEngine` 对每种证据 kind 重新读取归档字节、重算摘要、
  重核修订/digest pin；依赖遍历有 `maxDependencyDepth`（默认 64）上限。
- **时态与撤回**：项目文档索引用 `visibility_epoch` + 追加式 membership + receipt CAS，
  构建后 epoch 变化不复活已撤回语料；撤回/替换走新修订、历史仍可读。
- **未经核验发布**：`verifiedTableManifests` 只有在对应 `table-verification-receipt` 存在时
  才按“已验证表”返回，否则拒绝渲染为正式表；`answer-draft@3` 将 manifest/receipt refs
  纳入内容哈希，任何后续修改触发重新核验。
- **模拟/实机混淆**：合成数据通过 `dataMode: 'synthetic'` 显式标注；计算/查询输出携带
  `dataMode`；本阶段不涉及设备控制。

### 发现（记录）

- **F1（低 / 信息，未修复，已记录）**：`packages/adapters/extraction-document/src/structured/ingest-postgres-store.ts:317`
  对 JSONB 列 `document_version_ref` 仅做 `isRecord` 判断后 `as unknown as ResourceRef`，
  与同文件其它字段（`oneOf`/`optionalString`/`toCoverage` 等）不同，未做运行时形状校验。
  影响：该值由本 store 自身写入、非攻击者可控，当前流程不构成正确性缺陷；但若持久化行损坏，
  该断言可能掩盖问题。判定：release gate 内不扩大范围修复，记录为后续可直接加固点。
- **F2（低 / 设计取舍，接受）**：`060_structured_extraction_candidates.sql` 删除了
  `extraction_candidates_parse_fkey`。原因：结构化解析与文本/PDF 解析是两个解析家族，
  单一 FK 会拒绝全部结构化候选。候选的解析绑定改由不可变 `input_version.parseId` +
  来源 span 显式承载；租户/空间仍由 RLS 与 store 谓词强制。判定：接受，并在迁移注释中说明。
- **F3（信息 / 与已知限制一致）**：`typed-draft-writer.ts` 中内联表的 money 单元格与无
  unit/currency 轴的 compute 标量不直接生成 claim，而是声明限制
  （`money_requires_table_manifest` / `numeric_cell_no_unit`），交由正式表清单装配。
  与 §8 V03-036 限制一致，非缺陷。
