# 设计：A 阶段重塑为「Ontology 知识工作台」

状态：2026-10-15 设计稿（Codex 产出，待评审）。基线：main `065a43e`。
定位：在现有 A Core 之上补齐「工作入口、来源工作流、状态引导」，把 demo 感改成产品感。核心价值仍为可审核、可追溯、可固定版本。

## 0. 背景与问题

阶段 A（通用 Core）已验收合入 main，但产品形态被评「很 demo」：

- README 以「保存两行 CSV → 上传 → 建本体」开场，用户不知道如何开始使用，且「全是导入办公文件，很奇怪」。
- 缺少产品入口（第一屏）与清晰上手路径。
- 知识来源只体现了「手工上传文件」一种。

## 1. 目标形态

「通用知识工作台」：把某个业务领域，从**料源** → **可审核的行业资产** → **带依据的业务问答**串成能上手的工作流。两个工作对象：

- **行业工作区**：整理领域的术语、对象、关系、规则、动作，审核并发布可复用行业包。
- **项目**：挂载行业包，确认实际业务数据，完成带依据的任务与问答。

「本体生成助手」「业务实践助手」作为工作台内的辅助能力名称；用户先选要完成的工作，不必先理解 agent / mapping / 本体工程。

首期范围：三料源入口、两个工作台、真实待办与恢复路径、研究来源闭环、文件映射接入。数据库连接器、定时采集、OCR、自由爬虫、场景专业计算另行规划。

关键交互：首次进入显示业务目标输入 + 三料源 + 已有行业包入口，无需先选内置演示行业；已有工作优先「继续工作 / 需要你处理」；业务用户已有包可直接建项目；未选工作对象点料源时轻量选择用途；新建工作区首步只需名称+业务目标；权限/能力不足展示原因与恢复入口，模型未配置不影响已有资料/历史/确定性任务。

首页进度是阶段状态与明确计数，不显示无法解释的百分比；「来源已保存 / 来源可用于建模 / 资产已发布 / 项目可查询」分别表达。

### 1.2 主价值路径

```mermaid
flowchart LR
    A[业务领域或问题] --> B[行业工作区]
    B --> C[AI 搜寻公共资料]
    B --> D[上传资料]
    C --> E[来源确认与版本固定]
    D --> E
    E --> F[生成定义、规则、动作候选]
    F --> G[人工编辑与审核]
    G --> H[验证并发布行业包]
    H --> I[项目挂载固定版本]
    J[文件映射接入] --> K[记录、字段与身份确认]
    I --> K
    K --> L[事实、查询数据与文档索引就绪]
    L --> M[任务与问答]
    M --> N[已核验结果、依据、历史]
```

首次价值：行业维护者看到**第一组有真实来源、可改可审的候选资产**；业务用户得到**第一份可展开依据的已核验结果**。不得用「上传成功」或「生成了一张关系图」替代价值达成。

### 1.3 三料源

| 入口 | 用户操作 | 状态与输出 | 关键限制 |
|---|---|---|---|
| AI 搜寻生成 | 填业务目标/研究范围，确认外发内容与额度，开始调研 | 待开始→检索/归档→待确认来源→纳入建模→生成候选 | 研究产物不能直接发布或成为项目事实 |
| 自己上传 | 上传/粘贴，选用途，预览解析，确认来源性质 | 已保存→解析中→待确认/部分解析/失败→可用于建模或项目资料 | 上传不自动证明权威性 |
| 连数据源 | 选「文件映射」，选文件/sheet/列，预览规范值，确认映射 | 待映射→映射待确认→记录待确认→发布/构建中→就绪 | 明示是文件快照接入，不称实时同步 |

上传 CSV/Excel 按用途分流：**行业依据**（进工作区来源库，供定义/规则生成）或**项目记录**（进映射/确认/发布/物化）。可复用同一不可变原件，但两用途各自有成员关系、审核与授权，不能互相继承批准状态。「接入结构化数据」首期只做文件映射；数据库连接显示为规划能力及边界说明。

### 1.4 AI 搜寻的授权、费用与可信级别

开始前用简短确认面板说明：将向哪些搜索/模型服务发送哪些内容；允许搜索的域名/时间范围/目标；最多搜索次数、来源数、模型 token、时限；预计费用或「当前无法估算」及可强制执行的额度；只产候选、需人工确认。默认仅外发用户明确提交的公共研究 brief，不自动夹带项目记录/私有原文/历史问答/密钥。允许域名 = 部署/空间授权策略 ∩ 用户选择；输入域名不构成授权，模型不能扩大名单。

费用：调用前预留额度、调用后结算；重试/分页/并发共同扣减；有可信价格配置时展示金额估计并固定价格配置版本；无可靠报价则显示调用/token 上限，不伪造金额；用量未知保留未结算、不显示零成本、不自动继续消耗；用户主动追加调研是新的明确授权操作，失败重试不能借此重置原预算。

四级 trust tier 保留，UI 称「来源类别」，不用百分比：

| 契约值 | 展示 | 进入正式资产的条件 |
|---|---|---|
| `agent_researched` | AI 调研，待确认 | 不可直接支撑正式发布 |
| `public_standard` | 已确认公共标准/规范 | 人工确认发布者、适用范围、确切版本并固定来源 |
| `customer_authoritative` | 已确认业务权威资料 | 有授权人员确认业务权威性与适用范围 |
| `synthetic` | 合成验证资料 | 仅隔离验证，不能变为真实业务事实 |

**来源审核通过与可信类别提升是两件事**：接受某网页不代表它自动成为公共标准。厂商文档/行业文章/论坛等首期保留为研究参考，是否允许形成正式依据需单独定规则，不能随意塞进 `public_standard`。

| 行业 | 版本与历史 | 包版本、草稿演进、来源变化、审核记录 |

## 2. 技术设计

继续模块化单体、Fastify、React/Vite、控制 PostgreSQL、不可变工件与 jobs/outbox。

### 2.1 契约与端口

| 契约/端口 | 复用与调整 |
|---|---|
| `CandidateSource` | 保留 kind/trust tier/原件引用与摘要；增可读标题、研究任务关联、来源审核记录引用 |
| 来源审核命令 | 增 `workspaceId`、理由、期望修订、依据引用；核对来源属于路径中工作区 |
| `CandidateSourceStore` | 补游标分页与完整性；审核保留追加事件与幂等回执，当前行只作最新投影 |
| `ModelingBrief` | 复用 goal/domains/freshness/mustCover；补标准版本、粒度、命名约定 |
| 研究请求 | 来源数量与生成候选数量分别建模，不再让一个 `candidateLimit` 承担两种语义 |
| `ResearchExecution` | 新增不可变 brief/policy/budget pins、job 引用、阶段结果引用、覆盖统计、停止原因；状态沿用 Job |
| `SourceAdmission` | 新增来源审核版本→解析版本→工作区文档集版本的绑定与回执 |
| `WorkbenchOverview` | 新增工作摘要、计数、下一步、阻断原因、能力、固定修订的只读投影 |
| 来源能力投影 | 各入口支持格式/上限、是否可研究/归档/生成、不可用原因 |
| mapping/compute/provenance | 继续用原契约，增必要展示投影，不重定义业务真值 |

注意：`ModelingBrief.targetKinds` 实际仅接受 object/attribute/relation；规则/动作继续走现有 rule-action 生成服务，研究请求可分别引用两类生成目标，不把定义枚举扩成万能候选类型。旧版本请求保持可读；涉及必填审计字段或状态语义变化时用版本化请求 Schema。跨层数据用运行时 Schema；新端口放 contracts，不暴露 Fastify/React/pg/provider SDK 类型。

### 2.2 Application 服务与关键事务

- `WorkbenchOverviewService`：读授权工作区/项目/候选/jobs/readiness/发布状态，产生确定性下一步（不能用模型猜待办）。
- `CandidateSourceReviewService`：处理来源类别、审核理由、权限、CAS、幂等与审核沿革。
- `WorkspaceSourceAdmissionService`：将确认的来源解析、校验并纳入固定文档集。
- `ResearchWorkflowService`：复用 `WebResearchService` + ingestion，编排有界搜索、快照归档、结果登记与恢复。
- 现有 `ProjectMappingService`、物化服务、生成/审核/发布服务继续承担原职责。

来源纳入顺序固定：① 读并校验来源归属/当前审核版本/目标工作区草稿；② 授权读取快照，复核 bytes/digest/格式/解析覆盖；③ 生成可回读的逻辑 document/parse 绑定（不能把任意 `artifact` 当合法 `document`）；④ 创建新不可变 `GroundingDocumentSet`，显式携带 trust tier、来源审核引用、解析选项；⑤ 控制事务内重查来源版本与工作区 CAS，追加 admission 记录并更新草稿引用；⑥ 成功返回新草稿与纳入回执，失败保留「已审核、尚未纳入」可恢复状态。

来源审核不自动改写已发布包。来源撤回/重新分类产生新事件与可见性 fence；当前发布/使用重新判断依赖，历史保留原快照与当时审核信息。**新研究/上传路径必须显式记录类别**，不能借默认值把未确认来源变成客户权威资料。

### 2.3 研究执行与快照

```text
预检与授权回执 → 建立研究 Job 和预算账本 → 有界查询规划
→ 通过既有 gateway 的 web_search 执行 → 归档可引用快照 → CandidateSource 入库
→ 保存覆盖统计与停止原因 → 等待用户来源确认
```

快照归档是 `web_search` 受控实现的内部能力，不新增模型可自由调用的 `fetch_url` 工具。快照适配器：归档实际内容字节及来源元数据（不能把搜索摘要当完整网页）；校验域名/重定向/网络目标，限制超时/下载量/解压量；记录内容形态、抓取时间、provider 版本、digest、归档范围与限制；无可归档内容的结果标「仅发现链接，不能作正式依据」；原文与派生解析内容分别保存引用与摘要。研究默认可先沿用 A 的有界执行上限，再由研究策略收紧；`truncated`/`excludedCount`/无快照数量/失败数量都进入结果。研究等待人工确认后，后续候选生成作为明确新操作建立自身预算、关联同一工作流程，不是失败重试、不能偷偷重置额度。

### 2.5 前端与进度投影

复用并重组 `GuideHome`、`OntologyWorkspacePanel`、`WorkspaceSourcesPanel`、`DefinitionWorkbenchPanel`、`PackagePublicationPanel`、项目工作台与证据组件。导航沿用 query URL：

```text
/?view=start
/?assistant=ontology&workspace=<id>&tab=overview|sources|assets|review|validation|versions
/?assistant=business&project=<id>&tab=overview|data|review|tasks|history
```

兼容旧 `view=jobs/review/query/evidence` 与 run 深链接。刷新/前进后退/切换工作区保留正确上下文；不可见对象不能自动替换后继续原操作。

待办为服务端派生状态（无条件→选料源；有 proposed 来源→确认来源；已审核未纳入→完成纳入；有来源无候选→生成候选；…；能力齐备→开始任务）。概览投影不成为新的批准真值；点击执行时各业务服务重新授权与校验。`EvidenceSummary` 保留「事实前提」「规则原文」两轴，补来源类别/审核时版本/当前失效提示；不得把来源类别、检索排序或模型概率显示成「答案可信度」。

### 2.6 映射、计算与隔离

文件接入复用两层 mapping：`ImportMappingVersion`（原始列/JSON pointer→语义字段，含 sheet、表头摘要、精确单位转换、原文定位）与 `SemanticMapping`（批准记录→受控业务查询对象）。「文件数据源」首期从既有导入/membership/mapping/项目修订组合展示，不必马上加通用连接器实体。计算沿用 `OperationRegistry`、task binding、`data_query(kind=compute)` 与既有核验链；AI 只能提动作声明与参数候选，不能注册代码/计算金额/自行启用能力。

隔离：所有请求与 worker 身份来自可信上下文；来源审核检查 tenant/space/workspace，项目数据检查 project 与固定修订；研究索引/缓存/快照引用/用量/待办计数按范围隔离；候选来源不自动进入项目 corpus 或正式事实；项目采用工作区来源须经明确授权与成员绑定、固定版本；当前撤回状态影响新发布、历史回读不改写原答案；HTTP/local/MCP 共用服务与规则，不出现绕过审核的第二条入口。

### 2.7 持久化与迁移

保留 088，不编辑旧迁移。建议追加：

| 数据 | 存储 |
|---|---|
| 来源审核历史 | `candidate_source_review_events`（追加记录、理由、前后类别、actor、请求摘要） |
| 来源命令幂等 | 复用现有控制事务幂等机制，保存命令回执 |
| 来源纳入记录 | `workspace_source_admissions`（固定来源审核、解析、文档集、草稿引用） |
| 研究记录 | `workspace_research_runs`（关联既有 job/ledger、brief/policy refs、结果摘要） |
| 来源当前状态 | 在已有 `candidate_sources` 上加必要投影字段与索引 |
| 大文本与快照 | 继续保存于不可变工件，不塞进控制表 |
| 首页待办 | 首期查询投影，无独立待办真值表 |

所有键/唯一约束/外键/RLS 保持范围隔离。来源内容版本与审核修订分开。旧上传来源保留历史行为；缺少可证明审核事件时展示「历史路径确认」，不补造审核人/时间/理由。迁移编号实施时按实际 main 分配。

## 5. AI 设置：模型连接与选择（增量设计）

定位：空间内的**模型连接目录** + **按能力/工作对象分配** + **每次执行固定模型版本**。推荐「**新任务热切换、进行中任务保持原绑定**」；保留本机管理员对连接与密钥的管理限制。

### 5.1 现状与复用

现有 `ModelSettingsPanel` + `/api/v1/core/model-settings` 只有**一个整实例级的「生成模型」**配置（启用开关、服务地址、API 端点、协议、Core 平台模型 ID、服务商模型名、API Key 只写不回显、可清除），权限限本机 + platform-admin + 同 tenant/space，保存需重启生效，8s 连接测试（只证可达），决策 JEV 分开。关键是**把「配置保存」和「执行选择」拆开**。

复用：地址/端点校验、密钥留空保留 + 明确清除、脏表单守卫、取消/迟到响应保护、冲突保留输入（`ModelSettingsPanel`）；严格解析、拒绝读取响应夹带密钥（`model-settings.ts`）；可信身份/同 tenant·space/管理员/本机 Host·Origin/请求取消（`core-model-settings.ts`）；CAS 修订、地址变化不得沿用旧密钥、配置变化产生新模型标识（`core-local-model-settings.ts`）；每次执行绑定 ledger/signal、生成/JEV 独立适配器（`core-model-capabilities.ts`）。连接测试继续复用 8s / 64 KiB / 禁重定向 / 响应正文不回显。

### 5.2 产品设计

- **第一屏**在「当前工作」附近加一行能力状态：生成/研究/决策 JEV 的**模型名 + 来源（空间默认 / 工作区覆盖）+ 可用状态**；不显示密钥、连接详情或可误解为质量保证的「可信度」。
- **设置导航**：设置 → AI 设置 →（模型连接 | 默认与分配 | 生效详情）。
- **关键交互**：新建（允许保存未完成的禁用配置，保存不自动设为默认）；编辑（新修订；影响当前使用时提示「影响后续新任务」；CAS 冲突保留非密钥输入）；复制（只复制非敏感字段，新 ID、默认禁用、不复制密钥/范围/分配）；删除（有默认/能力/对象引用时拒绝，保留非敏感历史与墓碑）；测试（明示会发少量真实请求、可能计费；草稿可测试并标「未保存草稿」；改连接或密钥后旧结果失效）；设为默认（空间唯一，可明确「未配置」，删默认须指定替代或取消）；按能力分配（只列可用且能力匹配的配置；生成模型不能选作 JEV）；对象覆盖（继承/指定/停用，恢复继承与停用是不同操作）；清除密钥（明示影响范围；仍启用则须同操作停用，后续调用被阻断、不沿用旧凭据）。
- **作用域**：配置属于一个 `tenant/space`；可用范围为本空间全部工作对象或授权的工作区/项目集合；**项目不因挂载某行业包而继承其制作工作区的模型设置**。解析顺序固定：对象能力指定 → 对象默认 → 空间能力指定 → 空间默认 → 未配置；「继承」进下一层、「停用」终止；明确指定失效/缺密钥/被撤权返回阻断原因，**不静默改用另一服务商**；选择不改变既有执行策略/权限/工具名单/预算。
- **权限**：本机 `platform-admin`（连接 CRUD、测试、凭据、空间默认、能力分配、使用范围授权）；`profile-editor`（仅目标对象覆盖，不能改连接/密钥/扩范围）；执行者/只读用户/无权限用户按最小可见（无权限不返回名称/计数/地址/存在性）。受控选择会改变外发接收方，须同时校验对象权限、配置使用范围与部署允许目标。
- **状态与衔接**：未配置 / 未测试 / 最近测试通过（带时间与修订）/ 认证失败·超时·限流·协议不匹配（脱敏原因码，不显示 provider 正文）/ 被停用·凭据撤销·无使用权（阻断新调用，不自动切换）/ 分配冲突（返回最新修订、保留选择）/ 任务使用旧版本（「本任务固定 X；新任务 Y」）。AI 搜寻预检「研究模型+搜索+归档」并展示实际接收方；上传/结构化接入/人工审核不依赖模型。
- **新增 A-R09「管理模型连接」、A-R10「分配并解释生效来源」、A-R11「安全切换与无模型退化」**，纳入 A-R08 整栈验收。

### 5.3 技术设计

**契约（运行时 Schema）**：`ModelCapability`（闭集 generation/research/decision_jev，版本化扩展）；`ModelTargetScope`（可判别联合 space / industry_workspace(workspaceId) / project(projectId)）；`ModelConnectionSummary`（ID、名称、修订、适配类型、支持能力、启用、凭据状态、测试摘要）；管理员连接视图（加地址/端点/服务商模型名，不含凭据值）；`ModelAssignmentSet`（作用域、默认、各能力选择、修订；选择 = inherit/disabled/connectionId）；`EffectiveModelSelection`；`ExecutionModelBinding`（执行 ID、能力、配置修订、组件 VersionRef、分配修订与来源，不含密钥）；`ModelConnectionTestResult`。适配类型与协议分开（公司生成适配器沿用 openai-compatible/private；JEV 用现有独立适配器，不伪装成生成协议）；支持能力由已注册适配器 + 服务端校验确定，用户不能随意勾选；JEV 的 fallbackPolicy/阈值等保持现有执行配置，本设置不提供行为策略编辑。`GenerationPort`/`DecisionPort` 不合并；研究复用 `GenerationPort`，由调用入口明确传入用途，模型输出不能自行选择配置。

**端口/服务**：contracts 增 `ModelConnectionStore`、`ModelAssignmentStore`、`ModelSelectionResolver`、`ModelConnectionProbePort`、执行绑定存取端口（只传无密钥数据与不透明引用）；application 增 `ModelConnectionService`（权限/CAS/复制删除引用检查）、`ModelAssignmentService`（默认唯一性、作用域与能力校验）、`ModelSelectionService`（解析与生效投影）、执行绑定服务（固定并回读版本）；adapters 控 PG 存储/凭据托管/生成·JEV 探测与运行适配；composition 注入并把绑定版本装配为既有适配器（沿用 ledger/证据记录器/取消信号）。复用 `SecretResolver`/`SecretValue`。**`apiKey` 不进公共领域实体/模型调用契约/事件/jobs payload**；元数据与凭据分离（凭据先受控暂存，元数据事务成功后激活；失败可恢复清理；清除/撤销可重试幂等）。

**API（`/api/v1/core/ai`）**：`GET/POST/PUT/DELETE /model-connections`（含 `:id/copy`、`:id/credential` 写入·清除、`:id/test`）、`POST /model-connection-tests`（草稿）、`GET /model-options?...`、`GET/PUT /model-assignments`、`GET /effective-models`、`POST /model-change-previews`。路径/查询中的目标 ID 均不可信；tenant 来自认证、space 来自可信上下文，再验证目标资源归属。错误补充稳定原因码（`MODEL_NOT_CONFIGURED`、`MODEL_DISABLED`、`MODEL_CAPABILITY_MISMATCH`、`CREDENTIAL_MISSING`、`MODEL_IN_USE`、`MODEL_BINDING_REVOKED`）；跨范围统一不可见。

**前端**：保留 `?view=models` 深链接，增设置页签与目标参数，复用脏表单导航守卫；拆 `ModelConnectionsPanel`、`ModelConnectionEditor`、`ModelAssignmentsPanel`、`EffectiveModelSummary`（首页/两工作台/研究授权页复用）。切换空间/对象/配置或离开编辑页清空密钥；密钥不进 URL/localStorage/草稿恢复/前端埋点。

**生效：新执行热切换（推荐）**。分配提交后新执行用新选择；连接编辑产生新修订，新执行采用新修订。任务接受/授权阶段**固定配置、分配、模型组件版本**并持久化后再投递 job；同一执行的重试/恢复/并行用原绑定原预算原取消，不重新解析默认；不改已固定 profile，需换模型时经现有 profile 解析与 preflight 生成新快照；工作区生成服务静态 `modelRef`、部署级布尔能力投影、组件注册都要改成与执行绑定一致；历史按原绑定展示；**停用/清凭据/撤权有安全阻断效力**（阻止后续调用、取消能取消的请求；已被撤销执行的迟到结果不恢复不发布）；适配器安装/出站策略/凭据后端初始化仍可需重启。

**迁移**：① 读旧本地设置（无文件才用环境，损坏明确报错不静默回退）→ ② 建「原生成模型」连接（保留启用/地址/协议/模型名/旧标识映射）→ ③ 建空间默认（生成/研究在兼容能力内继承；原关闭继续关闭）→ ④ JEV 环境配置单独迁移为 JEV 连接 + `decision_jev` 分配（保持现有策略与依赖，不共用生成凭据）→ ⑤ 凭据迁入托管层，记录不含秘密的迁移标记，可重复执行不覆盖后续修改 → ⑥ 保留旧组件引用与历史（旧凭据不可用返回明确原因，不借新默认恢复）→ ⑦ 验证后切唯一真值，受控清除旧文件凭据 → ⑧ 从旧进程切到新管理模式安排一次部署重启，之后日常热切换。旧 `GET/PUT/POST test /core/model-settings` 保留显式 legacy 模式；迁移后旧接口返回 `MODEL_SETTINGS_MIGRATED`，不允许旧客户端覆盖新目录。

### 5.5 风险与未决

| 风险/未决 | 推荐处理与验收 |
|---|---|
| 通过选模型把数据发给未批准的服务 | 连接管理员维护可用范围；对象编辑者只能选批准项；研究授权绑定实际接收方与版本 |
| 本机限制被误当完整网络鉴权 | 保留 Host/Origin 限制并验证 socket 对端/可信代理边界；不因新增目录开放远程凭据管理 |
| 测试/运行成为 SSRF 或凭据转发入口 | 出站目标由部署管理员约束；保存/测试/运行统一目标校验；禁重定向、防 DNS 变化；内网地址仅明确授权 |
| 密钥经复制/日志/异常/审计/备份扩散 | 复制不带密钥；请求体与 Authorization 不记录；审计只记操作与非敏感版本；凭据存储与备份单独保护 |
| 热切换破坏固定 profile/重试/证据 | 每次执行固定版本；旧快照不改写；新配置经原 preflight；同任务不因默认变化换模型 |
| 清凭据与运行中任务冲突 | 明示会阻断后续调用；撤销 fence 及时生效；保留历史元数据，不承诺继续执行 |
| JEV 被误当通用生成模型 | 单独适配类型/探测/依赖校验；能力不匹配拒绝；既有 JEV 行为策略不变 |
| 凭据后端选型 | 本机优先 OS 保护的加密托管（Windows/Linux 实现与备份恢复在 N00 定案、N15 验证）；不默认扩为外部云密钥平台 |
| 旧客户端与回滚 | 明确 legacy/新管理模式切换；新模式禁旧写接口；回滚不能把新目录压回单配置 |
| 配置不可用时降级 | 显式原因 + 功能退化；不增自动多模型故障转移；结构化/人工/历史/确定性路径继续工作 |

N13 至少增加高风险用例：跨 tenant/space 直接 ID 访问与列表泄漏、跨工作区使用未授权配置、复制无密钥、同名不串用、并发改默认、地址变化禁止复用旧密钥、任务 A 固定旧版本而任务 B 用新版本、恢复不重新选择、撤销后迟到结果不发布、迁移重复/中断/损坏恢复、完全未配置模型时非模型路径与历史回读仍可用。
