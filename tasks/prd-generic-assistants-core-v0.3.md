# PRD v0.3 A：补足通用双助手 Core

日期：2026-09-29。状态：评审稿；尚未实现本文新增功能或合入 main。

总产品与造价 MVP 见[双助手 PRD v0.3](prd-ontology-and-business-assistants-v0.3.md)。用户确定的顺序是：**A 通用能力与公共前端验收进入 main → 活动场景同步主线 → B 造价专属功能与前端完成 MVP。** 本文定义 A 的有限交付范围，不把客户函数、真实价格或报价金标作为 A 的前置条件。

## 1. 要解决什么问题

当前主线可以导入、审核发布和查询少量已发布属性，但普通用户还不能从行业资料开始建立一套资产，再以自然语言完成有依据的业务任务。部分规划、规则和关系模块存在于研发或场景分支，未通过主线正常入口形成完整产品。

A 要交付两套实际可用的公共工作区。本体生成助手处理资料、定义候选、规则／动作、实例、审核和行业包发布；业务实践助手挂载行业包与项目数据，完成已支持的查询、规则判断、文档问答与注册计算任务，并提供核验、来源和历史。

行业、客户映射、业务函数、runtime、数据后端与前端场景模块分别装配。通用实现没有桥架、能源公式、客户税率或具体列名。必要的替换点必须保留；不要求在 A 建成可执行任意脚本的万能插件平台。

## 2. 输入、输出与有限范围

| 方面 | A 的交付 |
| --- | --- |
| 输入 | 行业边界与问题、代表性资料、草稿／发布定义、实际项目记录、确认操作、自然语言任务、授权组件配置 |
| 行业资产输出 | 可编辑定义／规则／动作候选；不可变发布包；身份／术语策略；标记为合成的验证样例 |
| 业务输出 | 待确认字段与原因；固定版本输入；事实表、关系结果、规则判定、引用片段或计算结果；已核验正文、证据、历史及 JSON 导出 |
| 资料格式 | UTF-8 文本、JSON、CSV、XLSX；格式／表结构及文件大小上限可见；PDF／扫描件／DWG 不作为本阶段已承诺格式 |
| 语义任务 | 属性／实体查询、有界关系导航、有限规则结论和依据查询；支持能力由发布包与运行配置共同决定 |
| 数据工具 | ontology_lookup、data_query、document_search、web_search 固定目录；compute 是 data_query 下的已注册动作能力 |
| 执行方式 | 已知依赖用固定计划；需补证时使用有界循环；同一控制器负责预算、取消与发布 |
| 查询与检索 | 实际批准项目数据的结构化查询；授权文本片段的索引／检索／有引用问答。首实现可复用 BM25，不强制向量库 |
| 不在 A 交付 | 桥架行业正式资产、客户报价函数、权威价表、造价专业表、金额业务签核、报价 XLSX |

规则第一批至少覆盖同实体比较／范围／缺失、有限 AND、不同条件分支的 OR、明确例外、一个受限关系前提和有限无环规则依赖。OR 不再只指同一条件的替代证据。规则不提供支撑不等于业务命题为 false；unknown、冲突与明确反证分开。

关系导航、关系前提、规则依赖层数、循环步数、检索条数及批次上限在 SPEC 中冻结。受限递归、更广逻辑、通用 OWL、任意 SQL／代码、无限多跳不作为本阶段隐含目标；超界返回不支持或不完整，不删条件后继续执行。

## 3. 用户与公共前端

行业维护者能创建行业工作区、上传资料、生成和编辑定义／规则／动作、验证实例并发布包。业务用户能新建项目、挂载版本、导入和确认记录、提问或执行可用任务、展开来源、导出并回读结果。发布和撤回由授权审核者完成，普通业务用户不能改变全局定义。

公共 UI 提供双助手入口、行业包／项目列表、资料和来源对照、定义与实例编辑、字段确认、任务状态、类型化结果、证据面板及历史。未配置功能显示原因和处理入口，不能只报 HTTP 错误后把整个页面留空。

前端预留明确的场景组合入口，挂载任务入口、参数表单、专业结果视图和导出行为。页面代码与声明行业包分开；公共页面不根据行业名称硬编码分支。B 的桥架参数、价表选择、报价表和金额差异由造价模块提供。A 的通用字段表与结果表必须能操作，无须先造万能表单设计器。

## 4. 用户故事与验收

以下为 PRD 验收故事，已拆为[本批任务](../.autoresearch/batches/v0.3-assistants/INDEX.md)；真实 GitHub 编号以 manifest 为准，Issue 创建不代表功能完成。与总体 PRD 的 US-001～011 共同定义建模操作；其余总体故事的通用机制由本文验收，造价含义由 B 验收。故事进入任务时继续按契约和依赖拆分；所有新增代码通过适用 lint、typecheck、测试与边界检查。

### US-001：使用公共双助手与场景挂载入口
**描述：**作为用户，我希望看懂两个助手并开始可用工作。
- [ ] 行业包与项目首页支持创建、继续、切换及刷新回读；没有造价模块时不显示默认报价操作。
- [ ] 挂载测试场景的任务／表单／结果视图时只改场景组合入口与配置，公共框架不新增行业判断。
- [ ] 任务缺能力、服务失败或无权限时保留页面和草稿，展示中文原因与恢复入口。
- [ ] 在浏览器核验真实可操作的两工作区、空态、错误态和挂载视图。

### US-002：解析资料并确认物理映射
**描述：**作为用户，我希望看见实际资料被读取到什么程度。
- [ ] 支持表中四类格式；CSV／XLSX 可选择 sheet、确认列对应、预览规范值与原始单元格。
- [ ] 资料与项目任务保存总数、成功、待处理、失败和修订；不支持的表头／结构定位提示，不默默猜列。
- [ ] 原始文件、解析版本、片段／sheet／row／cell 可定位；重复导入不丢原始行标识。
- [ ] 在浏览器核验分页、失败行、重复文件、修订与来源对照。

### US-003：从资料生成并审核行业资产
**描述：**作为行业专家，我希望资料变成可维护的类型、属性、关系、规则和动作。
- [ ] 按总体 US-002～007 生成有来源的定义／规则／动作候选；与实例候选分开，人工修改不被重试覆盖。
- [ ] 可编辑、拒绝、合并术语、修订端点／单位，展示版本差异；不支持的规则保存为不可执行。
- [ ] 动作声明只绑定已注册授权能力；模型建议代码、任意脚本和任意地址不能执行。
- [ ] 在浏览器核验完整候选生成、修改、冲突、拒绝和动作未绑定流程。

### US-004：用固定 Schema 抽取并确认真实实例
**描述：**作为用户，我希望抽取真正使用当前行业约束。
- [ ] 模型请求包含固定类型、属性、关系、单位和支持规则约束；受控服务检查实际请求内容。
- [ ] 保留原始／规范值和来源；精确数量不先转有损 Number，未知字段和关系端点进入待确认。
- [ ] 身份裁决、字段修改、批准／发布可追溯；重复实体不删除独立业务记录。
- [ ] 在浏览器核验提参、字段修改、同名异物、拒绝、关系端点及发布回读。

### US-005：验证并发布可挂载行业包
**描述：**作为维护者，我希望发布资产能用于另一项目。
- [ ] 发布前校验定义、规则支持范围、动作契约及能力需求；语义已发布和部署可执行分别显示。
- [ ] 合成实例隔离标记，用于规则／动作验证；不会成为真实事实或自动获业务批准。
- [ ] 不可变版本可导出和重新挂载，包含来源索引与差异；不含客户实例、真实价表或密钥。
- [ ] 在浏览器核验验证反例、发布阻断、版本查看、导出及新项目挂载。

### US-006：让批准项目数据进入实际查询
**描述：**作为业务用户，我希望任务使用刚刚导入的实际记录。
- [ ] 项目绑定确定的行业、mapping、数据来源与批准修订；数据就绪状态可读，未同步不冒称可查询。
- [ ] 正常接入流程将记录映射到授权可查询数据集，增量变更／删除策略明确；不读取启动演示快照来代替用户输入。
- [ ] 相同业务数据经不同客户列名／单位映射后语义一致，结果来源定位到各自实际物理对象。
- [ ] 在浏览器及 API 核验新导入数据、映射变更、失败恢复和跨项目读取拒绝。

### US-007：以自然语言提出受支持任务
**描述：**作为用户，我希望用业务问题查询数据，不需要学习 facts: 或内部 ID。
- [ ] 固定验证问题覆盖列表／属性、规则判断与解释、文档依据及已注册计算，路由到当前授权项目和能力。
- [ ] 歧义时给出选项或缺项；超范围问题明确拒绝／受限，不返回预设行业答案。
- [ ] 参数修改先展示具体差异供确认；生成 SQL／查询计划受 mapping、只读白名单及 Schema 校验约束。
- [ ] 在浏览器核验普通问题、澄清、变更确认、执行结果和不可用任务。

### US-008：查询有限规则结论与关系
**描述：**作为用户，我希望区分原始属性与规则推得的判断。
- [ ] 以独立样例验证比较／范围、有限 AND、不同条件 OR、例外、受限关系前提与无环依赖；缺信息不默认为 false。
- [ ] 实际调用已发布关系的有界导航，返回实体、关系版本、来源与完整性；不把字段 JOIN 或证据图当实体导航。
- [ ] 规则适用性、业务命题状态、来源冲突和截断分别表达；支持子集外的请求显式拒绝。
- [ ] 在浏览器及 API 核验规则正文、关系端点、OR 替代支撑、未知和超界状态。

### US-009：从结论展开规则与原文依据
**描述：**作为复核者，我希望看到完整业务依据并辨别证据缺口。
- [ ] 从结论展开实例前提→规则及版本→派生结果，并定位前提的原始片段／单元格。
- [ ] 规则规范原文经真实 parse／span 链定位，引用内容、locator 和 digest 一致，不只显示规则 ID。
- [ ] 来源撤回后按仍有效支撑增量更新；历史保留旧结果和当时支撑，当前与历史明确区分。
- [ ] 在浏览器核验支持撤回、替代依据、原文引用、缺证据与越权拒绝。

### US-010：执行版本化确定性动作
**描述：**作为业务用户，我希望明确的任务得到可复核计算结果。
- [ ] 示例动作通过正常 task／gateway／compute 注册链执行，固定输入、函数版本、授权范围和前置条件。
- [ ] 保存输入／输出工件、逐字段计算证据、调用状态与完整性；模型不能给缺失数值编造计算结果。
- [ ] 缺输入、未绑定函数、契约不兼容或函数故障有明确阻断和重试路径；同逻辑动作重试不重复有效执行。
- [ ] 在浏览器及 API 核验结果、未就绪、重复提交及工件回读；示例不冒称客户报价。

### US-011：核验并发布类型化业务结果
**描述：**作为用户，我希望可读正文与具体数据一致。
- [ ] writer 支持本阶段事实、规则、关系、结构化查询、原文引用和 compute 证据对应的类型化结果。
- [ ] 核验字段／主体／单位／时间／来源／版本／完整性及授权；错规则判定、错数值、错引用或错行绑定阻断发布。
- [ ] 发布有效性涵盖上述证据依赖；仅发布同一已核验版本，正文修改重新核验，SDK final 不能绕过控制器。
- [ ] 在浏览器核验表、正文、依据、失败原因及持久化后同版本回读；生成解释不另添事实。

### US-012：检索项目文档并生成有引用回答
**描述：**作为用户，我希望找到资料中的业务依据。
- [ ] 导入授权文本后有索引状态，能检索本项目实际片段并返回固定修订／span；失败或未就绪明确提示。
- [ ] 文档问答的事实依赖检索证据，经引用核验后生成最终回答；检索不到依据时说缺依据。
- [ ] 修订／撤回同步索引可见性；缓存、检索与模型上下文保持范围隔离，片段按上限返回并标明覆盖限制。
- [ ] 在浏览器及 API 核验新增资料可检索、旧修订、撤回、空结果、伪造引用和跨范围拒绝。

### US-013：在正常入口使用计划与有界循环
**描述：**作为用户，我希望任务可在需要时补证，并能停止。
- [ ] Template 支持已知步骤；动态 runtime 支持“查询不足→补查→完成”的有限测试路径，均由正常 HTTP 分派而非手动 Controller 启动。
- [ ] 策略设定步数、时间、模型／工具预算及无进展停止；补查、澄清和草稿修复共用 ledger，不重置额度。
- [ ] generation 与 JEV 分端口；JEV 按需决策，概率不能改变权限或证明答案正确；缺决策模型时明确可用降级策略。
- [ ] 在浏览器及 API 核验进度、取消、无进展、预算耗尽、澄清续跑和迟到结果不发布。

### US-014：保留修订、恢复和通用导出
**描述：**作为用户，我希望修改后保留旧结果，失败后有清楚的恢复办法。
- [ ] 输入、定义、mapping、函数与资料变更产生新修订，旧结果保存当时快照／证据；历史回读与固定版本复算分别标注。
- [ ] 发布响应丢失可由同一逻辑键读回；重启后正文与证据不变，支持的检查点恢复沿用原 ledger，不支持的组合明确提示。
- [ ] 结果可导出结构化 JSON，包含状态、版本和来源索引，权限与已核验页面一致；专业 XLSX 模板由 B 挂载。
- [ ] 在浏览器核验差异、失败重试、重启、历史、导出与错误状态。

### US-015：证明行业与组件真正可替换
**描述：**作为平台维护者，我希望场景接入不会改写公共框架。
- [ ] 交通与工业两行业、至少两种物理映射经相同公开契约产生独立金标结果，不在公共后端／前端新增行业判断。
- [ ] 复用并接通 Template／Pi 两 runtime、DuckDB／PostgreSQL 两业务查询后端、本地／真实 stdio MCP；在共同支持任务上结果／核验契约一致。
- [ ] 控制库 PostgreSQL 不算第二个业务查询后端；checkpoint 与不支持快照能力显式拒绝，不承诺任意 SDK 状态迁移。
- [ ] 合成计算函数及场景 UI 来自扩展装配；无客户端代码或真实价格进入通用包，适用架构边界测试通过。

### US-016：通用双助手整栈 E2E 与 main 发布验收
**描述：**作为测试负责人，我希望用户流程证明 A 能独立交付，再成为场景基线。
- [ ] 自动浏览器测试从原始合成资料生成定义／规则／动作，人工编辑审核后发布行业包，新建项目、挂载、导入实例并确认身份与字段。
- [ ] 普通提问分别完成属性查询、规则结论与原文解释、文档问答及注册示例计算，查看已核验正文／表格、来源、JSON 导出和历史；第二行业重复最小流程。
- [ ] 覆盖缺值、错单位、不同条件 OR、关系前提、缺能力、假引用／错结果、撤回、跨范围、取消／重试、重启；至少 1001 行并验证后页证据与完整性。
- [ ] 使用实际 UI／HTTP／Worker／Controller／持久层，不预置候选、派生结论或答案；CI 可重复清理自建数据、容器与命名卷。
- [ ] 受控模型验证与实际模型质量分别报告；真实模型评测固定输入／参考集并记录未验证限制，不用受控输出证明抽取质量。
- [ ] 适用 lint、typecheck、单元／集成／E2E 与边界检查通过并独立审查；同步 README、SPEC、迁移说明和完成清单，合入 main 后记录明确提交 SHA。

## 5. 功能要求

- FR-1：系统必须提供独立可操作的两个公共助手入口。
- FR-2：系统必须通过场景组合入口挂载专业 UI。
- FR-3：系统必须保存行业范围、目标问题和资料修订。
- FR-4：系统必须生成有依据的定义、规则和动作候选。
- FR-5：系统必须阻断不受支持的规则被启用。
- FR-6：系统必须只执行已注册并授权的版本化动作。
- FR-7：系统必须让实例抽取请求获得固定行业 Schema。
- FR-8：系统必须保存身份裁决与字段确认记录。
- FR-9：系统必须隔离合成样例与真实项目事实。
- FR-10：系统必须发布可重新挂载的不可变行业包。
- FR-11：系统必须按 mapping 查询本项目实际批准数据。
- FR-12：系统必须把受支持的自然语言问题转为授权任务。
- FR-13：系统必须保留规则未知、冲突和反证的区别。
- FR-14：系统必须报告关系导航与查询结果的完整性。
- FR-15：系统必须提供规则结论到原文的证据定位。
- FR-16：系统必须使索引可见性跟随资料修订与撤回。
- FR-17：系统必须对支持结果执行类型化硬核验。
- FR-18：系统必须只发布同一已核验结果版本。
- FR-19：系统必须以共享预算限制计划与循环。
- FR-20：系统必须阻止取消后的迟到结果发布。
- FR-21：系统必须保留历史结果的原快照与证据。
- FR-22：系统必须提供与已核验版本一致的 JSON 导出。

| A 内批次 | 主要工作 | 进入／退出条件 |
| --- | --- | --- |

| A3 可替换性与主线交付 | US-015～016、README、审查、合并 | 契约／E2E／工程检查通过，形成已验收 main 提交 |

同批次内部可按依赖并行，但 B 的场景专属实现以 A3 的主线基线为入口。B 的客户资源核对可提前进行。已验收的通用增量可以分 PR 回流 main；只有 A 整体退出条件通过才标阶段 A 完成。

优先复用现有通用研发工作线 feat/core-planning-provenance；其 35 项 WIP 是本次审阅时的快照，不是全部已完成或全部属于本阶段。按能力核对必要依赖、迁移编号、端口、正常装配和测试；不得整枝搬入未验收实验。Anker 分支中可复用的关系等能力亦按此方式提取，保留场景工作。

main 接收通用运行、公共 UI、契约、文档及隔离标记的通用验证样例。桥架、能源等专属资产／UI／函数保持各自场景模块和交付线；以后可复用且授权共享的资产单独审查回流，不把长期知识积累放在只有某分支才有的隐藏代码里。

合入 main 后，造价分支和其他仍在推进的场景先处理自己的 WIP，再同步明确基线并运行受影响回归。采用普通 merge，默认不改写已共享历史。分支操作见[分支管理](../docs/branch-management.md)。

## 8. 非目标与待细化

本期不做完整行业标准自动认证、全自动审核发布、任意行业／格式／数据库覆盖、无限推理、模型生成代码直接执行或客户生产系统写入。数据库、向量库与 DataOS 不因名称被预设为已可用；DataOS 继续只作为数据中台。

SPEC 阶段明确：候选／草稿版本模型、规则有限语法与状态、项目数据更新及查询快照、证据和 writer 扩展、runtime 接入、索引撤回、公共 UI 挂载与真实替换测试。沿用[既有技术 SPEC](spec-industry-semantic-agent-v0.2.md)的边界、授权、预算和同版本核验原则，新增行为必须更新契约，不用旧非目标阻断用户最新要求。

未确认的客户价格、图纸量算、报价函数权限和人工金标属于 B 的依赖，不阻断 A。A 的外部条件是实际公司模型 API 与评测资源；受控接口能验证机制，真实模型质量缺资源时记未验证，不能冒称已通过。
