# 本体推理 v-next 目标清单（对齐稿）

> 状态：**待对齐**，不是最终 SPEC。
> 背景：PRD v0.1/v0.2 把「全自动建模、递归推理、通用 OWL、全局最优」明确列为**非目标**；现拟将其中与愿景相关的部分**重新确立为目标**。本文只列目标、验收、边界与依赖，供其他 Agent 出方案；方案回来后再定 SPEC。
> 日期：2026-09-29

---

## 0. 一句话

把现有 core 从「**人工声明本体 + 有限规则 + 有界多跳的执行器**」，升级为「**数据驱动提取本体候选 + 专家定义最优本体 + 递归/多跳推理**」的 **发现器 + 推理机**。

- 现状 core：治理与执行很强（候选→审核→发布→证据→双时态→撤回），但**本体靠人写、规则靠人写、递归被禁、多跳有界**。
- 目标形态：LLM 从数据**提本体/规则候选**，专家**定义"最优本体"**作真值，引擎支持**多跳与递归**推理，全部可追溯。

---

## 1. 目标总览

| 编号 | 目标 | 当前状态 | 核心验收 |
|---|---|---|---|
| **G1** | 数据驱动的本体与规则**候选提取** | 🔴 基本没有（只有实例/关系候选抽取，无 schema 归纳） | 候选 vs 专家本体的结构对齐指标 + 人工节省成本 |
| **G2** | "最优本体"定义（专家真值）+ 版本化 | 🟡 有版本化定义/发布，无"专家共识"与金标机制 | 能作 G1 金标；可签核、可回溯、可演进 |
| **G3** | **多跳**推理（从有界升级） | 🟡 有有界关系导航（hop/fanout 限制） | 路径正确率 + 证据可回溯 + 超界显式 incomplete |
| **G4** | **递归**推理（受控子集） | 🔴 刻意禁止（环检测用于防环） | 递归正确 + 终止性 + 证据可追溯 + 撤回重评 |
| **G5** | 本体与推理**评测体系**（金标） | 🔴 缺 | 结构对齐 + 任务对齐 + 推理正确率 + false-pass/reject |

## 2. 逐目标详述

### G1 · 数据驱动的本体与规则候选提取
- **定义**：给定**行业范围 + 数据/资料**（文档、清单、规范、样本），由 LLM 提取**对象/属性/关系/规则**的候选，逼近"专家会定义的本体"。
- **输入**：行业范围声明 + 一批真实资料/数据。
- **输出**：候选本体（带**来源、置信、类型、单位**）+ 候选规则（条件/否定/例外/单位/适用范围）→ 进「候选→身份→审核→发布」。
- **验收（可测）**：
  1. 结构对齐：对象/属性/关系的 **recall / precision**、粒度与命名一致性（对照专家本体）。
  2. 任务对齐：用提取的本体跑下游任务（如造价报价）与黄金结果比对。
  3. 人工成本：专家从"从零写"到"审/改候选"**节省的时间比例**。
- **边界**：LLM **只提候选，不发布**；schema 扩展需显式人审；无来源/类型错误不得发布。
- **依赖**：G2（真值金标）、G5（评测）。

### G2 · "最优本体"定义（专家真值）+ 版本化
- **定义**：**最优本体 = 行业范围内、专家定义、最能代表业务语义的本体**；作为 G1/G5 的**真值与验收锚**。
- **输出**：专家本体库（版本化、可签核、可演进、可撤回）；专家共识记录。
- **验收**：能作 G1 金标；版本可回溯；本体变更有决策记录。
- **难点**：多专家可能不一致 → "最优"是**共识过程**，不是单一终点。
- **依赖**：无（但要先定"谁是真值"）。

### G3 · 多跳推理（升级有界）
- **现状**：core 有有界关系导航（`PublishedRelationNavigator` 类，hop/fanout/maxPaths 限制）。
- **定义**：支持**更深、更通用**的路径查询（沿关系链多跳、跨源连接），但**仍受预算/证据/权限约束**。
- **候选新增**：让**关系前提进规则**（现在规则不支持 relation premise）。
- **验收**：多跳路径**正确率**；路径每一步**证据可回溯**；**跨租户/超界/环**等反例；超界显式 `incomplete`（不静默漏）。
- **边界**：不做无限深度、不做无预算遍历。

### G4 · 递归推理（受控子集）
- **定义**：结论依赖结论的**递归/闭包**（如传递闭包、层级推导、自引用规则）。
- **验收**：
  1. 正例：递归闭包结果正确。
  2. **终止性**：收敛或不收敛时有上限/显式拒绝，不挂起。
  3. 证据可追溯：递归链每一步有支撑。
  4. 撤回/时态：支撑变化后重评；历史可复读。
- **难点**：递归 × 双时态 × OR 支撑 × 撤回 组合下的**终止性、单调性与可追溯**。
- **边界**：**受控递归子集**（如单调、有界深度/扇出），不是通用 OWL；不支持的必须**显式拒绝**，不得丢条件标真。

### G5 · 本体与推理评测体系（金标）
- **定义**：没有金标就无法验收"最优"和"推理正确"；本目标是提供**可度量的评测底座**。
- **输出**：专家本体金标集 + 任务黄金结果 + 指标口径。
- **指标**：结构对齐（对象/属性/关系）、任务对齐（下游任务）、人工成本、推理正确率、**false-pass / false-reject**、递归/多跳的终止与完整性。
- **依赖**：G2（真值）。**跨 G1/G3/G4 横切。**

## 3. 明确不做（本期边界，防 scope creep）
- 通用 OWL / 完整语义 Web 推理。
- 全自动**发布**（仍保留人审）。
- 无限深度 / 无限容量 / 全局最优的数学保证。
- 模型直接产出金额或业务结论（金额仍走确定性函数、结论仍走硬核验）。

## 4. 待对齐的关键决策（需要你拍板）
1. **真值是谁**：单一资深专家，还是多专家共识？谁签核"最优本体"？
2. **LLM 的角色**：只"提一次候选"，还是"迭代逼近 + 自评 + 用专家反馈回归"？
3. **递归子集边界**：允许哪些（传递闭包 / 层级 / 自引用）？禁止哪些（非单调 / 否定递归 / 跨实体递归）？
4. **多跳是否要"关系进规则"**：让规则能引用关系前提（现在不支持）？
5. **目标归属**：这是**独立平台立项**（新 SPEC），还是**造价项目的后续**？时间尺度是几个月？
6. **与造价的关系**：确认这些目标**不阻塞造价 MVP**，只在造价上做"内部加速器"验证？

---

## 5. 与造价项目的关系
- 造价是**第一个验证场**：有专家（造价师）、有数据（清单/图纸）、有黄金结果（人工报价）——正好能同时验证 G1（提本体候选）、G2（专家本体）、G5（评测）。
- 短期：**不阻塞交付**；G1 先当"帮 E1 写本体"的内部工具。
- 中期：把"LLM 提本体候选 → 专家审 → 发布"产品化；用造价黄金样本回归。
- 长期：G3/G4（多跳/递归）接进推理引擎。

## 6. 给 Agent 的出方案要求
针对 G1–G5，分别产出：
1. **能力定义与接口**（输入/输出/端口，遵守 core 的边界）。
2. **验收方案**（金标、指标、正反例）。
3. **技术路线**（可复用的 core 模块 + 需新建的部分）。
4. **风险与代价**（终止性、可验证性、成本、维护）。
5. **与 PRD 非目标的变更清单**（把哪些"不做"改成"做"，各自的新验收标准）。
