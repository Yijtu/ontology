## 本机怎么用已推送版本

服务已在 `D:/work/ontology/platform` 运行：API `http://127.0.0.1:3000/`，Web `http://127.0.0.1:5173/`，本地 PostgreSQL 容器健康，控制迁移 054—056 已执行。最后一次读取 `/api/v1/virtual-solix/state` 为 revision 0、35% SOC、无已选计划；这是检查时的状态，使用前可重新读取。运行连接放在被 Git 忽略的 `platform/.env.local`，不要把它或聊天里出现过的密钥提交到仓库。

直接打开[家庭能源计划页](http://127.0.0.1:5173/?profileId=home-energy-demo-long&profileVersion=1.0.0&view=energy)：

1. 默认场景为上午阴、下午晴、35% SOC、全天 ReserveSOC 20%。点“构建情景”→“生成计划”，等 `Selected`。顶部 Solar/Battery/Grid/HomeLoad 卡片来自归档计划同一时隙，可拖动滑块；数值带单位、来源、时间和 forecast/simulation 标记。
2. **执行前**把天气切到“上午阴、下午阴雨”，保持全天 20%，再构建/生成；上午 PV 不变、下午下降，旧计划在新版真正选中后变为 `Superseded`。
3. **执行前**把 ReserveSOC 改成 60%，生效窗口选“晚间 17:00 起保底”，再构建/生成；当前 SOC 仍显示 35%，查看晚间备电、成本和放电变化。
4. 对当前 `Selected` 计划点“请求模拟执行”。只支持 Virtual SOLIX `simulation`：96 个时隙各有 Requested→Accepted→Observed 与状态引用，`live` 明确拒绝。执行后下一场景从期末 SOC 与下一模拟时窗开始；合成日内负荷/天气/电价模板会重复，**不是真实第二天预测**，跨时窗不计算误导性的成本因果差。

首次安装或排障参照[README](../README.md)和[本地产品说明](local-product.md)。服务进程不会因切分支自动运行新代码；更新代码后按 README 重跑迁移（若有新迁移）并重启 `pnpm run dev:local`。现有服务基线是 `a163c07`，不要用 A4/D1 的未提交文件指导用户操作。
