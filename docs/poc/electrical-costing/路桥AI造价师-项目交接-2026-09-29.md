## 1. 项目一句话

**把客户现有的"人工算电缆桥架报价"流程，升级成"AI 从资料中提取关键参数 → 调用客户已有的确定性报价函数 → 输出结构化报价表 + 解释"，并保证全过程可复核、可追溯。**

- 领域：**电气桥架（电缆桥架/线槽支架，电气安装工程）**，**不是桥梁土建**。
- 定位：**产品研发序列内部立项**（非客户 POC），内部"发包给作战小队"，达成 MVP 有奖励，后续商业化按贡献持续奖励。
- 性质：一次"试错对赌"——MVP 做不出则不接。

## 2. 背景与来源

- 客户已有一套自有软件 **Blueprint OS**（Windows/Electron 客户端 + 线上后端 `api.omniai.net.cn`），能完成清单录入、BOM 复核、报价生成/审批、价格快照等，但本质是**"CRM / 多维 Excel"式的操作平台，含大量人工**，无真正 AI。
- 客户希望评估与己方合作，把"图纸、清单、工程背景、行业规则、既有报价函数"进一步结合，形成**更智能、可解释、可审计**的造价能力。
- 两条可能的合作形态：① 在既有平台上加 AI/本体能力；② AI 原生重构。**两者都是"表皮"，核心是造价问题本身。**（首期不重构客户完整系统。）

## 3. 范围与边界

### 做（首期 MVP）
1. 从**自然语言/图纸/清单资料**提取关键参数（材料、规格、工程条件、数量）。
2. 调用**客户既有的确定性报价函数**。
3. 输出**结构化报价表 + 解释**。
4. 保留**关键参数、计算依据、工具调用记录**，形成可交互、可复核、可追溯的链路。
5. 在**约定真实样本**上与人工造价结果直接比对。

### 不做
- 不重构客户完整系统；不覆盖全部工程品类（首期仅电气桥架）。
- 不训练/微调模型；不做图像模型微调（图纸走解析，见 §7）。
- 不接真实设备、不做生产部署、不做客户生产验收。
- 不由模型生成金额（金额一律来自确定性报价函数）。

## 4. 输入 / 交付 / 验收

### 输入
真实图纸、清单/规格、项目补充资料、行业造价规范、客户既有计价规则与试算函数、人工造价结果样本。

### 交付
`自然语言/图纸资料 → 提取关键参数 → 调用报价函数 → 结构化报价表及解释` 的闭环；保留参数、计算依据、工具调用记录。

### MVP 验收
| 维度 | 标准 |
|---|---|
| 真实性比对 | 在约定真实样本上，与人工造价结果**直接比对**（差异项可解释） |
| 可复核 | 报价过程每步可复核（规则 + 输入 + 调用记录） |
| 可追溯 | 每个数字/结论可回溯到来源与依据 |
| 可演示 | 形成可演示的交互原型 |

## 6. 技术底座：现有 core 平台

底座为现有 `ontology` 仓库的核心产品线分支 **`feat/main-core-product-20260928`**（通用"本体 + 智能体 + 工具 + 证据 + 核验 + 发布"框架）。

### 6.1 core 已具备（可承载本项目机制）
- 本体（对象/属性/关系）、语义发布、属性事实投影、增量物化、撤回与历史
- **有限规则引擎（含例外四态、OR 支撑）**——正好对应造价的"条件判断 + 规范例外 + 变更撤回"
- run 工作流、预算、工具网关、compute operation、类型化答案正文
- 硬核验、逐断言证据绑定、十进制精确比较
- 来源注册/探测、文档导入/解析/抽取候选、身份审核发布、UI 五视图

### 6.2 core 需补齐/回流的集成缺口（本项目硬依赖）
> core 状态盘点 K01–K09；以下 5 项直接卡住本项目，**建议从功能分支 `feat/local-poc-core-20260923@37f3feb` 回流**。注意 core 迁移已到 `056`，回流迁移必须重新编号。

| 编号 | 问题 | 影响 | donor 是否有补丁 |
|---|---|---|---|
| K01 | POST /runs 未分派 Controller；PublishedAnswer 只存 ID/hash，无可读正文 | 整条"输入→报价→输出表"跑不起来 | ✅ |
| K03 | 发布属性无法成为规则前提 | 造价规则拿不到材料/规格属性 | ✅ |
| K04 | 物化来源只读前 1000 条 | 真实清单/材料量大即漏 | ✅ |
| K06 | 行业 Schema 未进抽取提示 | 真实模型无法跨行业抽取 | ✅ |
| K07 | 已发布事实未接四工具 | 改数据不改变答案，无法"可复核" | ✅ |
| K08 | 规划/控制器运行策略未整合（缺 scopeRef、canonical runId） | run 幂等/路由不稳 | 部分 |
| K09 | 配置/导入 UI 未发布真实 profile | 无法从页面完成真实配置 | 部分 |

> 说明：core 分支近期已推进（含 multi-attribute facts、model host、planning runtime wiring），回流前请**重新核对最新提交**，以上缺口可能部分已闭合。

### 6.3 必须新建的三块
1. **行业包 `industry-packs/electrical-costing`**：材料 / 规格 / 工程条件 / 计价规则 / 报价结果 的对象、属性、关系、单位、身份范围、规则语法。
2. **计算扩展 `packages/extensions/electrical-costing`**：把客户报价函数封装成版本化 compute operation（如 `costing.quote`），确定性、输入 Schema、输出报价表+依据。
3. **图纸/资料提取链路**：清单/规格文本优先；DWG 分级（L3 GTJ/GCCP 导出 > L2 DXF 几何 > L1 图层/文字）；**扫描件/图片不做工程量复核**；提取结果进"候选→人工确认"。

## 7. 客户资料与配合现状

已起草**《客户资料与配合清单》**（对客文件，见附录 A 的评审结论），核心是让客户在国庆期间准备：

- **A 必需**：询价清单原件、历史黄金样本（含原始输入）、价格依据（板材/表面处理/加工费/配件等）、板厚口径、范围归属。
- **B 常见**：标准长度、盖板口径、配件未税成本表、图纸（辅助）。
- **C 配合**：资深造价师访谈（最关键）、访谈录制、报价流程 SOP、输出标准、报价函数可调用方式。
- **D 口径确认**：材料密度（7.85 vs 7.86 冲突）、折边余量、单节长度、税率、报价系数、板厚分档、损耗率、螺栓数量。

**清单评审发现的问题（需在发给客户前修正）**：
1. 编号层级断裂（无"一、二"却出现"三、四"）。
2. **含税/未税口径未标**（A3 与 D 的 13% 冲突风险）。
3. **价格时效/基准日缺**。
4. **计量单位与换算口径缺**（米/根/套/件/吨/组/颗）。
5. **费用范围缺**（运费/安装/包装/检测是否含）。
6. **黄金样本性质未明确**（对外报价 vs 内部成本、含税口径）。
7. **负例样本缺**（被退回/大改的报价）。
8. **工艺规则未要求导出**（系统已有"条件→加工费/损耗率"规则，应导出全量，不只访谈）。
9. **地区/标准范围未确认**。
10. **访谈保密/录制授权未写**。
11. 表述风险：开头"静态梳理客户端"改为"根据贵方演示资料整理"；板厚"两值"需解释各代表什么；图纸补"无图纸以清单量为准"。
